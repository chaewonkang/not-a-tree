# Not a Tree

**AI × 디자인 엔지니어링 스터디** — AI 시대에 소프트웨어를, 특히 인터페이스를 가장 잘 디자인하는 방법을 실무 차원에서 연구하고 실험하는 모임입니다.

> 이 저장소는 스터디의 모집 페이지이자, 앞으로 나올 산출물이 함께 발행되는 공간입니다.

---

## 무엇을 하나요

출발점은 이론입니다. 도구를 잘 쓰기 위해서가 아니라, 도구가 전제하는 것들을 다시 묻습니다. 사람은 색을 어떻게 지각하는지, 레이아웃은 어떻게 의미를 만드는지, 인터페이스가 인간의 인지와 어떻게 맞닿아 있는지 — 지금의 도구들은 이런 질문을 건너뛰고 있다고 봅니다.

다만 이론화 단계에만 머물지 않습니다. **엉성한 이론 → 엉성한 도구 → 엉성한 스킬**을 반복하며 점점 다듬어가는 방식으로 운영합니다.

### 우리가 붙들고 있는 질문

1. 구현의 대부분을 에이전트가 맡는 시대에, **인간 디자이너와 엔지니어의 전문성은 어디로 옮겨가야 할까요?**
2. 현재의 디자인 인터페이스는 디자이너의 의도와 설계를 충분히 표현할 수 있는 도구일까요?
3. 코딩 에이전트가 대부분의 구현을 처리할 수 있다면, 디자이너의 의도를 담은 **디자인 명세**는 어떻게 생겨야 할까요?
4. 디자인 지식과 감각을 기계가 실행 가능한 형태로 어떻게 변환할 수 있을까요?

## 운영 방식

| | |
|---|---|
| **기수** | 1기 · 6개월 |
| **규모** | 6명 (주최 3 + 모집 3) |
| **주기** | 격주 · 오프라인 |
| **장소** | OTP Company (서울시 중구) |

한 명의 발제자가 정한 주제를 한 달 동안 다룹니다. 매월 순환으로 발제를 맡습니다.

```
1–2주차   독서 및 에세이   각자 관련 책을 읽고 주제와 연관 지어 짧은 에세이 작성
둘째 목요일  세션 1          에세이 공유·상호 비평 → 문제와 결과물 형식 결정
3–4주차   결과물 제작      각자/팀별로 결과물 제작
마지막 토요일 세션 2          결과물 공유·비평 → 다음 달 주제 논의
```

## 산출물

매월 하나씩, 아래 형태 중 하나로 만들고 공식 웹사이트에 함께 발행합니다. (서로 배타적인 분류가 아니라, 하나의 결과물이 취할 수 있는 형태들입니다.)

- **저널** — 인문학적 스터디를 바탕으로 문제의식을 글로 정리
- **인공 언어 / 스크립트** — 디자인 의도를 컴파일 가능한 형태로 표현하는 언어 실험
- **자동화 도구** — 라이트/다크·고대비·색각이상 등 조합을 검사하는 접근성 스크립트
- **스킬** — 문서·스크립트·리소스를 묶어 코딩 에이전트가 바로 실행하는 형태

## 저장소 구성

| 파일 | 설명 |
|---|---|
| `index.html` | 모집 페이지 (본편) |
| `style.css` · `script.js` | 본편 스타일 / 인터랙션 |
| `index2.html` · `style2.css` | 초기 에디토리얼 버전 (아카이브) |
| `study-recruitment.txt` | 모집 문안 원본 |

바닐라 HTML/CSS/JS이며 빌드 과정이 없습니다. 로컬에서 보려면 `index.html`을 브라우저로 열면 됩니다.

```bash
open index.html          # macOS
# 또는 간단한 로컬 서버
python3 -m http.server
```
